03问题

学习的个性化鸿沟,从未被真正填上

每个学生都想学会,但「学会」这件事,今天仍然只为少数人设计。听听学生自己怎么说:

教材写得很好,但我看不懂、看不进去

→ 写书做课的人的认知逻辑,和我的并不匹配。

我不知道我为什么不会,也不知道该怎么办

→ 没有人能帮我,因为没有人真正了解我。

我喜欢在练习中学 / 我听不进课 / 我靠笔记……

→ 个性化学习习惯,从来没有被服务过。

结构性矛盾:大班教学顾不上个体差异,小班与名师昂贵且稀缺、无法复制共享。学习效率的转折点发生在学生掌握自己个性化学习方法的那一刻——但绝大多数人,从未等到这一刻。

04为什么是现在

政策与技术的双拐点

政策拐点 · 体系内需求

「人工智能 + 教育」写进国家战略

  • 《教育强国建设规划纲要(2024–2035)》明确 AI 赋能教育方向,试点持续加码。
  • 高校普遍面临「拥抱 AI」的升级任务,却缺少能承接落地的专门团队。
  • 意味着 to-B 有真实、持续、愿意买单的一方。
技术拐点 · 体系外机会

基座模型能力跨过「可用」线

  • 「一位有无限耐心、可低成本复制的一对一老师」第一次在技术上成立。
  • 把「学习」重做一遍,不再是修修补补,而是提出全新解法的机会。
  • 面向 C 端,这是一个革命性而非改良性的窗口。
夹缝里的窗口:传统教培无法自我革命,大模型厂商无暇顾及教育纵深——两边都到不了的地方,正是我们的位置。
05解法

一个认知引擎,两条产品线

两条路线的分叉点在于:体系内与体系外,多角色与单角色,增强与变革。

to-B · 体系内的增强

多角色教学平台

  • 服务学生 / 教师 / 教务多角色
  • 目标:让各角色的工作被 AI 辅助提效
  • 模式:母版打磨 → 换壳复制
◀ 工程化交付

认知引擎

认知建模
任务构造
个性化画像
长程记忆

to-C · 体系外的变革

Vibe Learning

  • 只服务一个人:自学的学生
  • 目标:让不会学习的人「被动」会学
  • 模式:数据飞轮,越用越懂你
算法深化 ▶

两条线客户不同、形态不同、商业模式不同——但共享同一个团队、同一套底座、同一条开发流水线。

06产品线一 · to-B

多角色教学平台 —— 增强与赋能

当下正在落地的产品线。平台拆成五个「助」的业务模块,共用同一套底层,各自面向不同角色、深浅不同。

助学

核心 · 重

给学生「轻引导式教学」——刻意做增强,不做替代。

助教

核心 · 中

帮老师发任务、批改、答疑,与助学构成师生闭环的另一半。

助研

重

科研知识库 + 论文写作辅助,复用同一套知识库引擎。

助管

薄 · 单点

全局学情看板 + 预警,先做一个核心功能立住。

国际交流

薄 · 单点

留学 / 交换项目问答,同样先立住一个核心功能。

核心闭环

助学 ↔ 助教 = 「超星学习通的 AI 版」:老师发任务 → 学生完成 → 全程嵌 AI。

交付模式:在首个高校客户身上打磨出一套成熟「母版」,之后扩展到下一所学校本质是换 IP、换壳复制——边际成本逐单递减。

07产品线二 · to-C

Vibe Learning —— 跟着感觉推进学习

整条产品只服务一个人:正在自学的学生。AI 构造任务、建模认知、个性化画像、长程监管,帮学生进入学习心流——让不会学习的学生「被动」地会学,让学习变得自然而然。

认知建模

不是问答机器人,而是持续建模「你懂什么、卡在哪」的学习引擎。

个性化路径

学习材料与任务按你的认知逻辑重新组织,而不是按作者的。

长程陪伴

记住每一次学习,画像随时间累积——越用越懂你。

市场定位:C 端剑指整个传统教辅培训行业(考研 / 考公 / 法考 / 雅思……),首个闭环课程从 408 计算机考研切入。

09商业模式

B 端现金牛,C 端增长期权

to-B · 多米诺骨牌

项目制交付 + 年度运维订阅

  • 单校项目数十万至百万级(量级示意)
  • 母版 → 换壳复制,每卖一所边际成本再降一点
  • 成本下行 × 营收累积,剪刀差早早张开

实线=营收 · 虚线=成本(理论示意)。B 端是团队的现金来源。

to-C · 数据飞轮

订阅制 / 课程制

  • 自有用户 → 行为数据 → 引擎变强 → 产品更好
  • 非线性复利,只在自有用户上转
  • 前期蓄势,赌一个指数拐点

实线=营收 · 虚线=成本(理论示意)。C 端是团队的增长期权。

两张图叠起来看:B 稳定的现金流为 C 的长期投入托底,直到 C 的指数营收接棒——这正是两条线必须一起走的原因。

10核心机制 · 外循环

B 端重开发,C 端重算法

每一个工具模块,都在两条线上各活一次:B 端交付它的基础版,C 端交付它的算法优化版。

B 线 · 全栈团队FULL-STACK → 工具模块「基础版」B 端交付 · 收入① → 移植PORT → C 线 · 算法团队ALGORITHM → 「算法优化版」C 端产品 · 收入②
01

一套模块,两次变现。研发成本被 B 端订单部分消化,C 端拿到的是「已被真实交付验证过」的底子。

02

算法迭代永远有靶子。优化版对照基础版,效果提升可度量——算法团队不在真空里做研究。

03

组织与业务同构。全栈工程师属 B 线、算法研究员属 C 线,分工天然清晰,考核各有标尺。

B 端的业务在于开发

本质是工程交付:比拼交付水准、复制效率与服务质量。

C 端的护城河在于算法

本质是学习效果:比拼认知建模、个性化与留存。

铁律:搬走能力,不搬走数据 —— 客户数据主权永远留在客户手里,两线之间流动的是算法、能力、经验与现金。
11竞争与壁垒

三类玩家都到不了的位置

玩家长处到不了的地方
传统教培 / 教辅
王道、文都等		 内容成熟、渠道深、品牌久 人力密集,无法规模化个性化;革自己命等于砸自己饭碗
通用 AI 助手
ChatGPT、豆包等		 模型能力强、用户量大 问一句答一句,无认知建模、无学习闭环,不为「学会」负责
教育信息化厂商
超星、雨课堂等		 校园渠道深、存量客户多 工具思维,AI 是贴皮不是原生;动不了自己的存量架构
开达教育 AI 原生认知引擎 + 双线互养结构:团队既懂模型又懂学习,B 线供血、C 线沉淀,轻装上阵

理念壁垒

对「个性化学习方法」的深刻认知——产品的每个决策都从学习本质出发。

技术壁垒

认知引擎随 C 端数据飞轮持续变强,后来者复制功能容易、复制积累难。

结构壁垒

「B 养 C」的双线模式本身:纯 B 端公司没有算法纵深,纯 C 端公司熬不过投入期。
