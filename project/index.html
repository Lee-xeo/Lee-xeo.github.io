团队内部 BP

我们到底在做一门什么样的生意

总的来说，我们有两条业务线：C 端 和 B 端。它们的客户不同、产品形态不同、商业模式不同，但底层的开发逻辑和团队本身是共享的。

以下信息涉及到团队内部信息，还请您不要随意转发、传播或在公共平台讨论，非常感谢。

两条产品线 一套认知引擎 增强 · 与 · 替代
核心图景

一个方向，两条路

两条路线核心的分叉点在于：体系内和体系外，单角色和多角色；辅助与变革。这决定了两条产品线长成完全不同的样子。

to-C · 体系外的变革

Vibe Learning

单角色 · 自学的学生
核心痛点
  • 学生学习意愿高，但缺少「良师」引路，缺少系统性方法。
  • 传统大班教学难以顾及个人差异，小班教学成本高昂。
  • 名师服务是稀缺资源，难以被复制和共享。
我的判断
  • 天赋固然重要，但有人指路对大多数人更关键。
  • 学习无聊、痛苦、高压是传统教学方法造成的，不是学习本身的错。
  • AI 是唯一能带来高效普惠个性化教育的技术。
to-B · 体系内的升级

多角色教学平台

多角色 · 学生 / 教师 / 管理
核心痛点
  • 政策鼓励高校拥抱 AI 赋能教育，但学校内部缺少承接的专门团队。
  • 体系天生有惰性，难以主动跟上 AI 浪潮。
  • 缺乏有效机制整合 AI 技术，实质提升教学效果。
我的判断
  • 体系内不需要变革，要的是赋能和升级。
  • B 端产品天然易于同质化，可以提供低成本克隆的一站式解决方案。
  • 背靠南大，我们已经有了第一个起点。

两条业务线产品 IP 天然隔离，底层沉淀同一个团队和开发流程。

产品线一 · to-C

Vibe Learning —— 跟着感觉推进学习

先说清定位：C 端业务线目前更多是我们的判断与蓝图，走的前沿理念。C 端业务真的开始盈利需要原始积累、运营和销售，所以落地会排在 to-B 稳住现金流之后——但它才是我们真正想改变世界的那一面。

需求

学生的需求其实很简单，也很复杂

谁都想学会知识，但谁都明白学会不容易。但是到底为什么不容易？尝试直面痛点：

  • 教材写得很好，但我看不懂/看不进去。→写书做课的人的认知逻辑和我并不匹配
  • 我不知道我为什么不会，我不知道该怎么做。→没人能帮助我，因为不了解我
  • 我喜欢在练习中学习/我不喜欢听课/我喜欢做笔记/我不擅长...→个性化学习习惯
方案

我们追求实现 Vibe Learning 这个概念形态

整条产品只服务一个人——使用产品进行学习学生。AI 通过构造任务、建模认知，个性化画像，长程监管，帮助学生进入学习的心流。AI 的最大作用是让不会学习的学生"被动"得会学，让学习变得更自然而然，所以我们叫它 Vibe Learning。

护城河

理念 + 技术

做 To C 业务的核心在于将先进的 AI 技术与教育理念相结合，形成独特的竞争优势。因此产品组成员必须对学习方法和教育理念具有深刻的自我认识。我们认为，学习效率曲线的转折点就发生在学生掌握自身个性化学习方法的时刻：不知你是否曾有过自主学习的顿悟时刻，领悟出适合自己的学习方法，如果有，那我们就是想让每个学生都尽早获得这种认识，从而不再让对学习方法的理解成为壁垒。

在现阶段，我们的首要护城河是理念，因为岗位需求画像的产品侧优先级更大于技术侧。

产品线二 · to-B

多角色教学平台 —— 增强与赋能

这是我们当下正在落地的产品线，也是团队的第一个试炼场。教学系统内的 B 端客户需要的是一个工具性平台——让学生、老师、教务等各自的工作都被 AI 辅助提效。

我们把平台拆成五个「助」的业务线：助学、助教、助研、助管、国际交流。它们共用同一套底层，但各自面向不同角色、深浅不同。

作为有产品追求的团队，我们想做的不是交差走人，而是一个真正好用的自研原生教学平台——这需要高品位的产品设计和够硬的技术支撑。

助学

核心 · 重

给学生「轻引导式教学」。注意：这里刻意不做 Vibe，走的是轻引导，而非替代。

助教

核心 · 中

帮老师发任务、批改、答疑——和助学一起构成师生闭环的另一半。

助研

重

科研知识库 + 论文写作辅助，复用同一套 KB 引擎。

助管

薄 · 单点

全局学情看板 + 挂科预警，先做一个核心功能立住。

国际交流

薄 · 单点

留学 / 交换项目问答，同样先做一个核心功能。

核心闭环

助学 ↔ 助教＝「超星学习通的 AI 版」：老师发任务 → 学生完成 → 全程嵌 AI。

最有意思的一点：B 端用户根本感觉不到 Vibe、也感觉不到背后的认知图——但引擎在后台照常运转。

引擎在场，体验隐身——同一套底层，能长出两种完全不同的产品。
我们的起点 · 南京大学

B 端的已有起点：一切从南大这个土壤开始

我们是一支南大内部的学生团队，在南大有先天优势和现有支持。就以现状可控的未来来说：校方出资、约束少、还有现成的师生团队。B 端和 C 端，都在这里拿到各自的「初始条件」。

初始条件

同一个校园，给两条线各发一手好牌

to-B · 第一个平台

成熟方案的最佳靶场

校方出资、限制少、自由发挥——理想的第一块试验田。

  • 用南大项目打磨出一套成熟 B 端方案的「母版」
  • 日后扩到别的学校，本质是换 IP、换壳复制
  • 在约束最少的南大做这个母版，成本最低
to-C · 天然试验田

现成的第一批测试用户

不用从零找人，校园里就有真实的学习者。

  • 老师自己开的课，天然的试点场景
  • 校内考研 / 雅思 / 四六级等刚需人群
  • C 端产品的冷启动，一开始就有真人可跑

要说清楚的是：南大是一片格外肥沃的土壤——给养分、给门、给第一批用户。但它只是起点，不是循环本身：种子能不能长成大树、自己开枝散叶，靠的是后面两条线各自转起来的「循环」。

两端交互

两条业务线，内外双循环

一条求稳、一条赌未来。它们客户不同、节奏不同，却能通过资金、能力、经验彼此支撑。但先要立一条底线——它决定了两端之间到底能流动什么。

搬走能力，不搬走数据

先声明清楚：B 端客户对自有数据享有产权保护，把平台交付给学校后，平台上的一切数据主权在学校——我们不能、也不会把它导出来喂 C 端。所以两端之间流动的，是团队沉淀的算法、能力、经验、内容、现金，唯独不是原始数据。

内循环 · 线内的复利引擎

各自转各自的圈，形状还不一样

to-B · 多米诺骨牌

一张牌，推倒下一张

驱动力是模板复制 + 背书，线性级联，每张更省力。

南大（第一张） → 成熟克隆体 + 背书 → 换壳微调到下一所 ▸ 每卖一个，边际成本再降一点
to-C · 数据飞轮

越转越快的正反馈

驱动力是数据 × 模型，非线性复利，只在自有用户上转。

自有用户 → 行为数据 → 引擎变强 → 产品更好 ↻ 更多用户 → 更多数据，飞轮越滚越快
理想模型 · 成本 vs 营收

把账画出来：两条线随时间的形状

投入成本 营收收入 横轴 = 时间 · 纵轴 = 金额（理论示意，非实际数据）

B 端 · 现金牛

成本随「换壳复制」越走越低，营收稳定累积——剪刀差早早张开，成为团队的现金来源。

C 端 · 增长期权

前期投入大、后期持续加码，赌一个指数拐点——营收一旦接棒，便是主升浪。

两张图叠起来看：B 稳定的现金流为 C 的长期投入托底，直到 C 的指数营收接棒——这正是两条线必须一起走的原因。
外循环 · 团队级资产账户

两个内循环，共用同一个账户存取

B · 多米诺每推倒一张牌
存一笔
⇄
越攒越厚算法 · 流程
经验 · 人才
⇄
C · 飞轮每转一圈
存一笔

团队、资金、开发经验、那套共享引擎——两条线都往里存，也都从里取。账户越厚，下一张多米诺越好推、下一圈飞轮越快转。这才是「团队和底座共享」真正的含义。

两端之间 · 到底在输送什么

流动的是成果，不是数据

B → C

现金流养 C 端研发 · 入校通道让 C 端能在真实课堂里试点 · 场景 know-how 与失败反馈打磨产品 · 背书带来信任。

C → B

C 端飞轮转出的更强引擎换壳装进 B 端交付 · C 端自制的课程内容可作为 B 端「助学」的现成资源。

铁律：流动的永远是能力、模型、内容与现金——数据主权，留在各自手里。
